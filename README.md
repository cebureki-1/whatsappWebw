# WhatsApp Chat Archive

Расширение для Chrome и Microsoft Edge. Оно архивирует открытую переписку WhatsApp Web настоящими снимками области сообщений и сохраняет PDF, ZIP или оба файла. Снимки и текст не отправляются на сервер.

Архив — локальная копия экрана. Он не подтверждает подлинность переписки и не имеет юридической силы.

## Установка готовой сборки

1. Установите [Node.js 20+](https://nodejs.org/) и в папке проекта выполните:

```bash
npm install
npm test
npm run build
```

2. Готовое расширение лежит в папке `dist`. В Chrome и Edge можно выбрать либо `dist`, либо саму папку проекта: корневой `manifest.json` ссылается на файлы внутри `dist`. Без `npm run build` значков и скриптов там не будет.

### Chrome

1. Откройте `chrome://extensions`.
2. Включите «Режим разработчика».
3. Нажмите «Загрузить распакованное расширение».
4. Выберите папку `dist`.

### Microsoft Edge

1. Откройте `edge://extensions`.
2. Включите «Режим разработчика».
3. Нажмите «Загрузить распакованное».
4. Выберите ту же папку `dist`.

После установки обновите вкладку `https://web.whatsapp.com/`. Content script подключается к уже открытой странице только после перезагрузки.

Во время разработки команда `npm run dev` пересобирает `dist` при изменениях. На странице расширений нажмите «Обновить», затем обновите WhatsApp Web.

## Как пользоваться

1. Откройте WhatsApp Web, войдите в аккаунт и выберите нужный чат.
2. Нажмите значок расширения.
3. Укажите дату начала. Дата окончания необязательна: без неё архив идёт до последнего сообщения, которое уже было в чате в момент запуска. Новые сообщения задачу не удлиняют.
4. Выберите PDF, ZIP или оба формата и название архива.
5. Нажмите «Начать архивирование».

Дальше расширение само прокручивает ленту сообщений вверх до выбранной даты, затем идёт вниз и снимает только область переписки. Боковая панель, шапка, поле ввода и интерфейс расширения в кадр не входят.

Окно расширения можно закрыть: задача живёт в service worker. Если браузер перезапустит фоновую страницу, задача встанет на паузу. Нажмите «Продолжить» или скачайте уже снятые кадры.

Кнопки:

- «Пауза» и «Продолжить»;
- «Остановить» — кадры сохраняются, архив помечается как неполный;
- «Скачать результат» — доступна, когда есть хотя бы один кадр и съёмка не идёт;
- «Удалить временные данные» — стирает кадры из IndexedDB и состояние задачи.

Процент выполнения не показывается: длина истории заранее неизвестна. Видны этап и число сохранённых кадров.

Если выбранной даты нет в загруженной истории, расширение останавливается и предлагает «Продолжить» с фактически доступного диапазона. Пустой архив в этом случае не создаётся.

«Скачать результат» собирает файл в текущем окне. Пока идёт сборка, окно лучше не закрывать. «Открыть в отдельной вкладке» нужно только если хотите оставить панель на весь экран.

Границы периода — целые местные календарные дни. Даты с точками читаются как ДД.ММ.ГГГГ. Дата со слэшем, где и день, и месяц не больше 12, не угадывается. Если в том же чате встретится однозначный пример вроде 13/06/2026, этот порядок применяется к остальным. Иначе задача остановится с пояснением, а не сохранит неверный диапазон.

## Что попадает в файл

PDF: титульная страница А4 с названием чата, запрошенным и фактическим периодом, временем экспорта, числом кадров и пометкой полноты. Дальше переписка идёт одной лентой сверху вниз: повтор соседних снимков вырезается, а лента режется на обычные листы А4. Низ страницы продолжается наверху следующей, без пустого разрыва и без повторного экрана. Так файл можно печатать. Кириллица встроена шрифтом Noto Sans (лицензия OFL, файл `assets/fonts/OFL.txt`).

ZIP: те же непрерывные куски как `0001.png`, `0002.png` и далее, плюс `manifest.json` с параметрами и статусом полноты. Имена очищаются от символов, запрещённых в Windows.

Длинный чат режется на части: до 60 исходных кадров в одном PDF и до 200 в одном ZIP. Общий предел задачи — 1500 кадров. При остановке или ошибке уже снятые кадры можно скачать; такой архив помечен как неполный, причина указана в PDF и в `manifest.json`.

## Разрешения

| Разрешение | Зачем |
| --- | --- |
| `https://web.whatsapp.com/*` | Content script только на WhatsApp Web: прокрутка и чтение видимых дат. Другие сайты не запрашиваются. |
| `activeTab` | Снимок делается после нажатия на значок расширения и только у видимой исходной вкладки. |
| `storage` | Настройки и небольшая контрольная точка задачи. Сами картинки туда не пишутся. |
| `scripting` | Повторно подключить content script, если страница не обновлялась после установки. |
| `alarms` | Заметить перезапуск service worker и поставить задачу на паузу, а не продолжать вслепую. |
| `offscreen` | Обрезать снимок до области сообщений. В service worker нет холста. |

`tabs`, `downloads`, `<all_urls>`, аналитика и удалённый код не используются. Скачивание идёт через локальную ссылку на файл.

## Как устроено

- `src/popup` — интерфейс на русском языке;
- `src/content/content-script.ts` — команды странице;
- `src/whatsapp/adapter.ts` — поиск ленты, дат и границ. Только DOM, прокрутка и скриншоты, без внутренних модулей WhatsApp;
- `src/archive/runner.ts` — шаги задачи, их можно гонять без Chrome;
- `src/background/service-worker.ts` — оркестрация, `chrome.tabs.captureVisibleTab`, пауза при смене вкладки, чата, размера или масштаба;
- `src/offscreen` — обрезка PNG;
- `src/export` — PDF (`pdf-lib`) и ZIP (`jszip`);
- `src/storage` — IndexedDB для кадров и `chrome.storage.local` для состояния;
- `src/future/extensions.ts` — пустые точки для второго этапа: скрытие номеров в пикселях, локальный OCR и Word. Кнопок для них нет.

Между снимками выдерживается пауза не меньше 700 мс. Повторный кадр пропускается только если прокрутка реально не сдвинулась. Одинаковые по тексту сообщения не удаляются.

Селекторы в адаптере — ориентиры по публично известной разметке (`#main`, `#pane-side`, `data-id`, `data-pre-plain-text`, заголовок чата). В этой среде живой WhatsApp Web не открывался, поэтому они не объявлены проверенными. Если страница не сходится, расширение показывает диагностику и не сохраняет пустой архив.

## Проверка

Автоматически проверено (`npm test`):

- русские и английские даты, «Сегодня» и «Вчера», местная часовая зона;
- отказ угадывать неоднозначные даты со слэшем;
- расчёт обрезки при дробном масштабе и обрезка краёв периода;
- переходы паузы, смены чата, перезапуска service worker, остановки и неполного экспорта;
- сценарий «поиск даты → кадры по порядку → граница архива» на подставной странице;
- отказ снимать другую вкладку и отказ продолжать другой чат;
- адаптер на похожей разметке и отказ на пустой странице;
- PDF с кириллицей и ZIP с `manifest.json`;
- модель виртуальной ленты: шаг 82% и покрытие всех сообщений.

`test-fixtures/virtual-chat.html` — отдельная имитация виртуализации. Это не WhatsApp Web и не доказательство совместимости.

Нужно проверить вручную на живом WhatsApp Web:

- короткий чат;
- длинный чат с подгрузкой истории;
- дата, которой нет среди сообщений;
- старая история, которую WhatsApp больше не отдаёт;
- сообщения с картинками;
- масштаб браузера 100%, 125% и 150%;
- смена вкладки и смена чата;
- закрытие окна расширения во время съёмки;
- пауза, продолжение и остановка;
- скачивание неполного результата;
- что PDF и ZIP открываются, а в кадр не попали список чатов и поле ввода.

Если диагностика пишет, что панель `#main` или `data-id` не найдены, разметка WhatsApp изменилась. Сообщите, какие пункты диагностики красные: по ним можно поправить адаптер, не сохраняя пустой файл.
